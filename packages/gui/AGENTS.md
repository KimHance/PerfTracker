# packages/gui

CLI 를 감싸는 **로컬호스트 웹 GUI**. 브라우저에서 adb 를 부를 수 없으므로 서버 계층이 필수다:
`perftracker gui` 가 로컬 HTTP 서버를 띄우고, 그 서버가 core 를 부르고, 화면은 서버의 JSON 만 본다.

디자인 정본은 [`docs/design/gui/HANDOFF.md`](../../docs/design/gui/HANDOFF.md) 다 — 색·간격·카피가
픽셀 단위로 적혀 있고, 이 모듈은 그것을 코드로 옮긴 것이다.

## 지금 있는 것 / 없는 것

| | 상태 |
| --- | --- |
| 화면 전체 (설정·측정 중·기록·다이얼로그·오버레이) | **있음** |
| 계약(`src/contract/api.ts`)과 그것을 만족하는 목업 클라이언트 | **있음** |
| `perftracker gui` 서버 (`src/server/`) — 실기기로 세션 전체 검증 완료 | **있음** |
| 세션 대시보드 | **없음.** 기록을 열면 CLI 로그만 남는다 (핸드오프 범위 밖) |

## 디렉토리

| 경로 | 무엇 | 무엇을 모르는가 |
| --- | --- | --- |
| `src/contract/` | 서버와 웹이 공유하는 유일한 계약 | **core 를 모른다.** core 타입을 그대로 흘리면 화면이 수집 사정에 묶인다 |
| `src/server/` | HTTP · 라우팅 · core 호출 · `runs/` 읽기 | 웹을 모른다. `view.ts` 가 core → 계약 번역의 **유일한** 자리다 |
| `src/web/state/` | 전역 상태 · 리듀서 · 파생값 | React 를 모른다 (`StoreContext.tsx` 만 예외). DOM 없이 테스트된다 |
| `src/web/format/` | 시간 · 명령 · 스펙 문자열 | 순수 함수. 상태도 API 도 모른다 |
| `src/web/api/` | `ApiClient` 인터페이스 + `http` / `mock` 두 구현 | 화면을 모른다 |
| `src/web/effects/` | **기기에 닿는 모든 흐름** | 컴포넌트를 모른다. 결과를 액션으로만 되돌린다 |
| `src/web/components/` | 표시 | `fetch` 를 모른다. `useStore()` 로 상태를 읽고 effects 를 부른다 |
| `src/web/styles/` | 토큰 + 컴포넌트 클래스 | 값은 전부 `var(--*)`. 컴포넌트에 hex 를 적지 않는다 |

## 깨면 안 되는 것

1. **컴포넌트는 `fetch` 를 부르지 않는다.** 기기 접촉은 전부 `effects/` 를 지난다.
   어디서든 서버를 부를 수 있으면 "지금 무엇이 기기를 만지고 있는가" 를 아무도 답할 수 없고,
   core 의 규칙 1(측정 창 안 기기 접촉 0회)이 화면 쪽에서 조용히 깨진다.
2. **측정 중에는 기기로 아무것도 나가지 않는다.** 마킹의 정본은 브라우저가 아니라 **활성 세션
   포인터 파일**이고, 거기 쓰는 core 의 `appendMark` 는 `AdbClient` 를 아예 받지 않는다.
   브라우저에 들고 있으면 새로고침에 사라지고, 무엇보다 같은 세션에 `perftracker mark` 로
   남긴 마킹을 정지할 때 덮어쓴다 — 두 입구가 같은 자리에 쓴다.
3. **지표 지원 여부를 화면이 판단하지 않는다.** 서버가 doctor 와 같은 경로(`collector.supports(env)`)로
   채워 준 것을 그린다. 화면이 SDK 표를 들고 있으면 "된다고 했는데 안 되는" 상태가 생긴다
   — 실제 판정은 SDK 뿐 아니라 그 기기에 perfetto 데이터소스가 등록됐는지에도 달려 있어
   표로 환원되지 않는다.
4. **한 기기는 동시에 한 세션만.** 다른 탭이 점유한 기기는 선택 불가로 그린다
   (`state/derive.ts` 의 `busySerials`). 두 세션이 한 기기를 잡으면 나중 것이 앞 것의
   Perfetto 세션을 밀어내고 두 result.json 이 같은 트레이스를 나눠 갖는다.
5. **모르는 값을 지어내지 않는다.** `null` 은 `-` 나 `미상` 으로 쓰고 0 이나 빈칸으로 바꾸지 않는다
   (core 규칙 3 이 화면까지 이어져야 사람이 "0 이라고 쟀다" 와 "못 읽었다" 를 구분한다).
6. **목업이 기본이 되지 않는다.** `?mock` 일 때만 목업이고, 그때는 화면 상단에 배너가 뜬다.
7. **저장 위치를 화면이 정하지 않는다.** 서버가 `EnvView.outDir` 로 알려 주고 화면은 표시만
   한다. 예전에는 브라우저가 `'runs'` 를 박아 보내서, `gui -o /tmp/x` 로 띄우면 파일은
   `runs/` 에 쌓이고 목록은 `/tmp/x` 를 읽어 **측정은 성공했는데 기록이 하나도 안 보였다.**
8. **끝나지 않은 세션은 기록이 아니다.** `start` 가 run 디렉토리를 먼저 만들기 때문에,
   그냥 훑으면 진행 중인 세션이 `길이 0ms · 경고 0` 인 완료된 기록처럼 목록에 뜬다.
   기준은 `endedAt` 이고 규칙은 `server/runs.ts` 에 있다.

## 상태

전역 상태 하나, 리듀서 하나 (`state/reducer.ts`). 상태 라이브러리를 들이지 않은 것은 취향이 아니라
계약이다 — 상태 전이를 `state/actions.ts` 의 목록으로 전부 셀 수 있어야 한다.

탭은 `{ 기기, 앱, 이름, 옵션, 마킹, phase, startedAt }` 을 **독립으로** 들고 있다.
전이는 `setup --(측정 시작)--> running --(정지)--> setup(초기화) + 기록 추가` 뿐이다.

### 서버가 정본이다 — `sessions/loaded`

측정 중인 탭은 **화면의 기억이 아니라 서버의 세션 목록에 맞춘다** (`reducer.ts` 의
`syncSessions`). 첫 화면에서 한 번, 측정 중에는 3초마다 부른다. 한 번에 세 가지가 맞춰진다:

| | |
| --- | --- |
| 서버엔 있는데 화면엔 없음 | 탭을 되살린다 (새로고침 복구 · CLI 로 연 세션 표시) |
| 화면은 측정 중인데 서버엔 없음 | 밖에서 끝났다. 탭을 설정 화면으로 되돌린다 |
| 둘 다 있음 | 마킹·미지원 지표를 갱신한다 (`perftracker mark` 가 여기로 들어온다) |

**여러 번 불려도 결과가 같아야 한다** — 기기(serial)로 짝을 맞추는 이유다. 이게 깨지면
3초마다 탭이 늘어난다.

이것이 없던 시절에는 새로고침 한 번에 기기가 "다른 탭에서 측정 중" 으로 잠긴 채 그 탭이
존재하지 않아, GUI 안에서는 정지도 새 세션도 불가능한 막다른 길이 됐다.

## 실행

```bash
# 실제로 쓰는 방법 — 서버가 화면과 API 를 함께 서빙한다
npm run build && npm run build:web
npx perftracker gui                     # 127.0.0.1 의 빈 포트, 브라우저 자동 실행

# 화면만 손볼 때 — vite 개발 서버(5173)가 /api 를 7333 으로 프록시한다
npm run gui
#   http://localhost:5173/?mock         목업으로 화면 전체 (기기 불필요)
#   http://localhost:5173/?mock=empty   기기 0대 빈 상태

npx vitest run packages/gui             # 리듀서 · 파생값 · 포맷 · effects · 서버
```

서버는 **127.0.0.1 에만 바인딩한다.** 붙어 있는 기기에 adb 를 보내고 run 디렉토리를 지울 수
있는 서버를 같은 네트워크의 다른 사람에게 열어 줄 이유가 없다 — `--host` 옵션이 없는 것은
빠뜨린 것이 아니다.

## 알려진 것

- 폰트(Barlow / Barlow Condensed)를 Google Fonts 에서 받는다. 오프라인이면 `system-ui` 로
  떨어진다 — 로컬 도구가 폰트 때문에 안 뜨면 안 되기 때문이다. 자체 호스팅은 남은 과제.
- 핸드오프의 "알려진 이슈"(마킹이 쌓이면 정지 버튼이 밀림)는 정지 버튼을 마킹 블록 **위**로
  올리고 목록에 `max-height` 를 걸어 해결했다.
