# packages/gui

CLI 를 감싸는 **로컬호스트 웹 GUI**. 브라우저에서 adb 를 부를 수 없으므로 서버 계층이 필수다:
`perftracker gui` 가 로컬 HTTP 서버를 띄우고, 그 서버가 core 를 부르고, 화면은 서버의 JSON 만 본다.

디자인 정본은 화면마다 하나씩 있다 — 색·간격·카피가 픽셀 단위로 적혀 있고, 이 모듈은 그것을
코드로 옮긴 것이다.

| --- | --- |
| 측정 화면 | [`docs/design/gui/HANDOFF.md`](../../docs/design/gui/HANDOFF.md) |
| 세션 보고서 | [`docs/design/report/HANDOFF.md`](../../docs/design/report/HANDOFF.md) |

## 지금 있는 것 / 없는 것

| | 상태 |
| --- | --- |
| 화면 전체 (설정·측정 중·기록·다이얼로그·오버레이) | **있음** |
| 계약(`src/contract/api.ts`)과 그것을 만족하는 목업 클라이언트 | **있음** |

| 세션 보고서 (`src/web/report/`) | **있음.** 기록을 누르면 `?report=<id>` 로 새 창이 열린다 |

## 디렉토리

| 경로 | 무엇 | 무엇을 모르는가 |
| --- | --- | --- |
| `src/contract/` | 서버와 웹이 공유하는 유일한 계약 | **core 를 모른다.** core 타입을 그대로 흘리면 화면이 수집 사정에 묶인다 |
| `src/server/` | HTTP · 라우팅 · core 호출 | 웹을 모른다. `view.ts` 가 core → 계약 번역의 **유일한** 자리다 |
| `src/web/state/` | 전역 상태 · 리듀서 · 파생값 | React 를 모른다 (`StoreContext.tsx` 만 예외). DOM 없이 테스트된다 |
| `src/web/format/` | 시간 · 스펙 문자열 · 시작 **예고** | 순수 함수. 상태도 API 도 모른다. 실행된 명령은 서버가 적는다 |
| `src/web/api/` | `ApiClient` 인터페이스 + `http` / `mock` 두 구현 | 화면을 모른다 |
| `src/web/effects/` | **기기에 닿는 모든 흐름** | 컴포넌트를 모른다. 결과를 액션으로만 되돌린다 |
| `src/web/components/` | 표시 | `fetch` 를 모른다. `useStore()` 로 상태를 읽고 effects 를 부른다 |
| `src/web/styles/` | 토큰 + 컴포넌트 클래스 | 값은 전부 `var(--*)`. 컴포넌트에 hex 를 적지 않는다 |
| `src/web/fonts/` | 자체 호스팅 글꼴 (latin subset 6개 · 89KB) + OFL 라이선스 | 이 페이지는 외부로 요청을 보내지 않는다 |
| `src/web/report/` | 세션 보고서. **매니페스트 팩토리** — 아래 절 참고 | 측정 화면의 상태를 모른다. `result.json` 만 읽는다 |

## 보고서는 팩토리다

`src/web/report/` 는 지표마다 컴포넌트를 만들지 않는다. 데이터 모양이 여섯 가지뿐이고
(`stat` `distribution` `series` `bars` `delta` `pairs`), **각 지표가 `manifest.ts` 에서 자기
모양과 데이터 위치를 선언**하면 렌더러는 모양만 안다.

    지표가 늘어난다  →  manifest.ts 에 한 줄
    새 모양이 나온다 →  그때만 kind 를 하나 늘린다

이 도구는 실제로 필드가 계속 는다 — `cpu.device_timeline` · `memory.system_timeline` · 앱 빌드
속성 다섯이 한 번에 들어온 적이 있고, 그때 화면에서 고칠 곳이 매니페스트 말고는 없어야 한다.

| 파일 | 무엇 | 무엇을 모르는가 |
| --- | --- | --- |
| `read.ts` | 경로 읽기. **필드 부재 / `null` / 값** 세 상태를 가른다 | 나머지 전부 |
| `format.ts` | 포맷터 · 상태 라벨 | 데이터 구조 |
| `manifest.ts` | 블록 선언 — **유일한 확장 지점** | 렌더링 |
| `axis.ts` `blocks.ts` `header.ts` | 기하 계산 · 결측 판정 (**순수 함수**) | React · DOM · 이벤트 |
| `*.tsx` | 그리기만 | 계산. 좌표는 받아서 쓴다 |

화면은 `?report=<run id>` 로 뜬다 (`web/main.tsx`). 라우터를 들이지 않은 것은 경로가 둘뿐이기
때문이고, 서버는 `GET /api/runs/:id/report` 로 `result.json` 을 **검증 없이 그대로** 낸다 —
여기서 zod 로 걸면 필드가 없던 시절의 세션이 화면에 아예 안 뜬다.

계산과 그리기를 가르는 이유는 core 의 `sources/` ↔ `toDomain.ts` 와 같다 — "선을 어디서
끊는가" 같은 판단이 브라우저 없이 테스트돼야 한다.

**입력은 `result.json` 그대로다.** 이 모듈만 계약이 다르고 그것이 의도다 —
이유는 `contract/api.ts` 의 `ReportDocument` 주석에 있다.

### 보고서에서 깨면 안 되는 것

- **`null` 은 `0` 이 아니고, `MISSING` 은 `null` 이 아니다.** 값 없는 초에서 선을 잇지 않는다.
  누적 카운터(`sampling: 'cumulative'`)는 0초가 없는 것이 정상이라 결측으로 세지 않는다.
- **버킷은 하나도 빠짐없이 그린다.** 값이 0인 칸도 그린다 — 분포는 어디가 비어 있는가가 곧
  정보이고, 있는 칸만 그리면 축이 세션마다 달라져 두 결과를 나란히 볼 수 없다.
  `breakAfterEmptyBuckets` 가 `Infinity` 인 이유이고, 데이터 쪽도 같은 규칙이다
  (`collectors/hwui` 가 154칸을 0까지 그대로 낸다).
- **항목 설명은 툴팁이다.** 막대 아래 줄로 깔면 항목 다섯짜리 카드가 열 줄이 되고, 읽는
  사람이 먼저 보는 것(개수와 비율)이 글에 묻힌다. 뷰모델에는 그대로 두고 렌더러가 정한다.
- **판정하지 않는다.** 임계선·점수·등급 없음. 색은 계열 구분에만 쓴다.
  `references`(구글 기준치)는 이 화면에서 쓰지 않는다 — 표시에도, 비교에도.
  예외는 `debuggable === true` 하나이고, 그것은 판정이 아니라 **아래 숫자를 어떻게 읽어야
  하는지를 바꾸는 측정 조건**이다.
- **못 잰 것을 숨기지 않는다.** 결측이어도 카드가 사라지지 않는다 — 없어진 카드는
  "이 도구가 원래 안 재는 것" 처럼 보인다.
- **시간축은 하나다.** `maxT` 를 화면 전체에서 한 번 계산한다(`axis.ts`). 지표마다 축을
  따로 잡으면 나란히 놓인 두 그래프의 같은 x 가 서로 다른 초를 가리킨다.
- **마킹과 시계열은 0초가 다르다.** `offset_ms` 는 세션 시작(호스트 시계), `t_s` 는 트레이스
  시작(기기 시계) 기준이라 실측 0.82초 어긋난다. `session.trace_start_offset_ms` 로 옮기고,
  **그 값이 `null` 이면 옮기지 않는다** — 0으로 가정하면 틀린 자리에 맞는 척 찍힌다.
  축의 오른쪽 끝도 세션 길이가 아니라 `trace_span_ms` 에서 나온다.
- **같은 것을 두 번 보여주지 않는다.** 렌더에는 트레이스와 프레임워크 두 출처가 있는데,
  분포를 두 장 두고 `전체`·`마감 넘김` 을 각각 내놓았더니 "어느 게 진짜냐" 로 읽혔다.
  **분포 카드는 하나이고 프레임워크 것이다** (`metrics.hwui.data.histogram`) — 안드로이드
  Vitals 가 보는 모집단·값이고 버전 하한이 없어 sdk 30 에서도 그려진다. 트레이스 분포는
  `result.json` 에 그대로 있고 **화면에서만** 뺐다. 테스트가 카드 하나를 지킨다.
- **화면에 안 그린다고 안 재는 것이 아니다.** "못 잰 것을 숨기지 않는다"(아래)는 *결측*에
  대한 규칙이고, 같은 것을 두 경로로 잰 값 중 하나를 화면에서 고르는 것은 다른 일이다.
- **매니페스트에 없는 지표는 개수를 남긴다.** 조용히 버리면 새 지표가 생겨도 아무도 모른다.

## 깨면 안 되는 것

1. **컴포넌트는 `fetch` 를 부르지 않는다.** 기기 접촉은 전부 `effects/` 를 지난다.
   어디서든 서버를 부를 수 있으면 "지금 무엇이 기기를 만지고 있는가" 를 아무도 답할 수 없고,
   core 의 규칙 1(측정 창 안 기기 접촉 0회)이 화면 쪽에서 조용히 깨진다.
2. **측정 중에는 기기로 아무것도 나가지 않는다.** 마킹의 정본은 브라우저가 아니라 **활성 세션
   포인터 파일**이고, 거기 쓰는 core 의 `appendMark` 는 `AdbClient` 를 아예 받지 않는다.
   브라우저에 들고 있으면 새로고침에 사라지고, 무엇보다 같은 세션에 `perftracker mark` 로
   남긴 마킹을 정지할 때 덮어쓴다 — 두 입구가 같은 자리에 쓴다.
3. **지표 지원 여부를 화면이 판단하지 않는다.** 서버가 doctor 와 같은 경로(`collector.supports(env)`)로
   채워 준 것을 그린다. 화면이 SDK 표를 들고 있으면 "된다고 했는데 안 되는" 상태가 생긴다
   — 실제 판정은 SDK 뿐 아니라 그 기기에 perfetto 데이터소스가 등록됐는지에도 달려 있어
   표로 환원되지 않는다.
4. **한 기기는 동시에 한 세션만.** 다른 탭이 점유한 기기는 선택 불가로 그린다
   (`state/derive.ts` 의 `busySerials`). 두 세션이 한 기기를 잡으면 나중 것이 앞 것의
   Perfetto 세션을 밀어내고 두 result.json 이 같은 트레이스를 나눠 갖는다.
5. **모르는 값을 지어내지 않는다.** `null` 은 `-` 나 `미상` 으로 쓰고 0 이나 빈칸으로 바꾸지 않는다
   (core 규칙 3 이 화면까지 이어져야 사람이 "0 이라고 쟀다" 와 "못 읽었다" 를 구분한다).
6. **목업이 기본이 되지 않는다.** `?mock` 일 때만 목업이고, 그때는 화면 상단에 배너가 뜬다.
7. **화면은 실행된 명령을 조립하지 않는다.** 서버가 자기가 한 일을 응답의 `command` 로 실어
   보내고 화면은 그것을 그대로 찍는다 (`server/command.ts`). 예외는 하단 시작 바의
   **예고**(`format/preview.ts`) 하나 — 아직 실행 전이라 서버에게 물어볼 것이 없다.
   이름이 `command` 가 아니라 `preview` 인 것은 예고와 기록이 다른 것이기 때문이다.
8. **저장 위치를 화면이 정하지 않는다.** 서버가 `EnvView.outDir` 로 알려 주고 화면은 표시만
   한다. 예전에는 브라우저가 `'runs'` 를 박아 보내서, `gui -o /tmp/x` 로 띄우면 파일은
   `runs/` 에 쌓이고 목록은 `/tmp/x` 를 읽어 **측정은 성공했는데 기록이 하나도 안 보였다.**
9. **앱 목록에는 버전을 싣지 않는다.** 사람이 읽는 버전은 `dumpsys package <pkg>` 를 앱마다
   따로 불러야 나온다 (82개면 왕복 82번). 대신 `versionCode` 를 실었더니 `2126060861` 이
   사람 읽는 자리에 앉아 아무 쓸모가 없었다 — **고른 앱 하나만** `appDetail` 로 읽는다.
10. **기기 목록이 바뀌면 탭의 선택을 다시 맞춘다** (`reducer.ts` 의 `reconcileSelection`).
    케이블을 뽑고 새로고침하면 목록에서 기기가 사라지는데, 탭이 그 serial 을 계속 들고 있으면
    화면에는 아무것도 선택되지 않은 것처럼 보이면서 `측정 시작` 만 활성이다 — 누르면 없는
    기기로 세션을 연다. **측정 중인 탭은 예외다**: 케이블이 빠져도 세션 포인터는 살아 있고,
    여기서 지우면 되찾을 길이 사라진다.
11. **끝나지 않은 세션은 기록이 아니다.** `start` 가 run 디렉토리를 먼저 만들기 때문에,
   그냥 훑으면 진행 중인 세션이 `길이 0ms · 경고 0` 인 완료된 기록처럼 목록에 뜬다.
   기준은 `endedAt` 이고 규칙은 core 의 `session/runs.ts` 에 있다 (CLI 의 `runs` 와 공유한다).

## 상태

전역 상태 하나, 리듀서 하나 (`state/reducer.ts`). 상태 라이브러리를 들이지 않은 것은 취향이 아니라
계약이다 — 상태 전이를 `state/actions.ts` 의 목록으로 전부 셀 수 있어야 한다.

탭은 `{ 기기, 앱, 이름, 옵션, 마킹, phase, startedAt }` 을 **독립으로** 들고 있다.
전이는 `setup --(측정 시작)--> running --(정지)--> setup(초기화) + 기록 추가` 뿐이다.

### 서버가 정본이다 — `sessions/loaded`

측정 중인 탭은 **화면의 기억이 아니라 서버의 세션 목록에 맞춘다** (`reducer.ts` 의
`syncSessions`). 첫 화면에서 한 번, 측정 중에는 3초마다 부른다. 한 번에 세 가지가 맞춰진다:

| | |
| --- | --- |
| 서버엔 있는데 화면엔 없음 | 탭을 되살린다 (새로고침 복구 · CLI 로 연 세션 표시) |
| 화면은 측정 중인데 서버엔 없음 | 밖에서 끝났다. 탭을 설정 화면으로 되돌린다 |
| 둘 다 있음 | 마킹·미지원 지표를 갱신한다 (`perftracker mark` 가 여기로 들어온다) |

**여러 번 불려도 결과가 같아야 한다** — 기기(serial)로 짝을 맞추는 이유다. 이게 깨지면
3초마다 탭이 늘어난다.

이것이 없던 시절에는 새로고침 한 번에 기기가 "다른 탭에서 측정 중" 으로 잠긴 채 그 탭이
존재하지 않아, GUI 안에서는 정지도 새 세션도 불가능한 막다른 길이 됐다.

## 실행

```bash
# 실제로 쓰는 방법 — 이 한 줄이 빌드까지 한다. 서버가 화면과 API 를 함께 서빙한다
npm run gui                             # 127.0.0.1 의 빈 포트, 브라우저 자동 실행
npx perftracker gui -p 7333             # 옵션이 필요할 때만 CLI 를 직접 부른다

# 화면만 손볼 때 — vite 개발 서버(5173)가 /api 를 7333 으로 프록시한다
npm run gui:dev
#   http://localhost:5173/?mock         목업으로 화면 전체 (기기 불필요)
#   http://localhost:5173/?mock=empty   기기 0대 빈 상태

npx vitest run packages/gui             # 리듀서 · 파생값 · 포맷 · effects · 서버
```

서버는 **127.0.0.1 에만 바인딩한다.** 붙어 있는 기기에 adb 를 보내고 run 디렉토리를 지울 수
있는 서버를 같은 네트워크의 다른 사람에게 열어 줄 이유가 없다 — `--host` 옵션이 없는 것은
빠뜨린 것이 아니다.

## 알려진 것

- **이 페이지는 외부로 아무 요청도 보내지 않는다.** 글꼴(Barlow / Barlow Condensed)은
  `src/web/fonts/` 에 자체 호스팅한다 — `latin` subset 6개 · 89KB. Barlow 에 한글 글리프가
  없어 본문 한국어는 어차피 `system-ui` 로 떨어지므로 전체 subset 을 받을 이유가 없고,
  `unicode-range` 가 그 경계를 그린다. 라이선스는 OFL 1.1 (`fonts/OFL.txt`).
- 핸드오프의 "알려진 이슈"(마킹이 쌓이면 정지 버튼이 밀림)는 정지 버튼을 마킹 블록 **위**로
  올리고 목록에 `max-height` 를 걸어 해결했다.
- **`.blueprint` 코너 마크(`+`)는 다이얼로그에만 있다.** 핸드오프(§디자인 노트)는 primary
  버튼에도 두라고 하지만, 이 GUI 의 버튼은 알약 모양이라 모서리 바깥의 `+` 넷이 윤곽을
  흐렸다 — 사용자 요청으로 뺀 의도적 이탈이다.
