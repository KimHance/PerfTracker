# Claude Code 에 붙여넣을 프롬프트

아래 블록을 그대로 복사해서 `PerfTracker` 리포지토리에서 Claude Code 에 붙여넣으세요.
(먼저 이 핸드오프 폴더를 리포지토리 안에 두거나, 경로를 실제 위치로 바꿔 주세요.)

---

## 1) 전체 구현 (한 번에)

```
PerfTracker CLI 에 로컬호스트 웹 GUI 를 추가하고 싶다.

디자인 핸드오프가 ./design_handoff_perftracker_gui/ 에 있다. 먼저 다음을 읽어라:
- README.md — 화면별 스펙, 색/타이포/간격, 카피, 상태 모델, CLI 연동 매핑이 전부 들어있다
- screenshots/ — 렌더된 화면 7장
- "PerfTracker GUI.dc.html" — 디자인 프로토타입 (레퍼런스일 뿐, 그대로 쓰지 말 것)

프로토타입 HTML 은 프로덕션 코드가 아니다. 이 리포지토리에 맞는 스택으로 다시 구현해라.
안의 기기/앱/기록/지표 수치는 전부 목업이니 실제 CLI·core 호출 결과로 대체해야 한다.

시작 전에 다음을 파악해서 나에게 계획을 먼저 보고해라:
- packages/cli, packages/core 의 기존 구조와 공개 함수 (특히 runDoctor, listDeviceSummaries,
  loadLabeledApps, beginStart/startSession, listActiveSessions, stopSession, extractRun)
- runs/ 디렉토리의 session.json / result.json 스키마
- GUI 를 어떤 형태로 띄울지 제안 (예: `perftracker gui` 서브커맨드가 로컬 HTTP 서버를 띄우고
  정적 프론트엔드 + JSON API 를 서빙. 브라우저에서 adb 를 직접 못 부르니 서버 계층은 필수)
- 프론트엔드 스택 선택 근거 (리포에 이미 있는 것 우선)

계획에 합의하면 구현한다. 반드시 지킬 것:
- 세션은 동시 여러 개. 브라우저 탭처럼 상단 탭바로 분리하고 탭마다 독립 상태를 가진다
  (기기/앱/이름/옵션/마킹/경과시간). 최소 1개는 남아야 하고, 측정 중인 탭을 닫으면 확인 받는다.
- 한 기기는 동시에 한 세션만. 다른 탭이 점유한 기기는 선택 불가로 표시한다.
- 지표 지원 여부는 GUI 에 하드코딩하지 말고 doctor 결과를 그대로 쓴다.
- 대기 구간은 재사용 로딩 오버레이 하나로 처리한다 ({label, command} 만 받는 전체 화면 컴포넌트).
  고정 지연이 아니라 API 응답까지 유지한다.
- 측정 중에는 기기에 adb 를 보내지 않는다는 기존 원칙을 깨지 말 것. 마킹은 서버 메모리에
  보관하다가 정지 시 result.json 의 marks[] 로 기록한다.
- 기록(history)은 항상 최신 상태. 여러 탭이 동시에 끝나도 즉시 반영된다.
  이름 변경(인라인), 삭제(확인), 전체 지우기 지원.
- 기록 클릭 시 대시보드는 아직 미정이다. 라우팅 지점만 만들어 두고 화면은 만들지 마라.

작업은 단계별로 커밋하고, 각 단계 끝에 실행해서 확인 가능한 상태로 만들어라.
```

## 2) 단계별로 진행할 때

한 번에 다 시키는 게 부담되면 이렇게 쪼개서 순서대로 주면 됩니다.

**1단계 — 서버/API**
```
./design_handoff_perftracker_gui/README.md 의 "CLI 연동" 절을 읽고, GUI 용 로컬 HTTP 서버를
`perftracker gui` 서브커맨드로 추가해라. 프론트엔드는 아직 만들지 말고 JSON API 만:
doctor, devices, apps(기기별), start, status, stop, runs 목록/이름변경/삭제.
기존 core 함수를 재사용하고 CLI 와 로직이 중복되지 않게 해라. 각 엔드포인트 수동 확인 방법도 알려줘.
```

**2단계 — 셸 + 탭**
```
README 의 "화면 구조", "1. 헤더", "2. 탭 스트립" 을 그대로 구현해라.
screenshots/01-setup-device-app-selected.png 과 맞춰라.
다크 토큰은 README "Design Tokens" 그대로. 탭은 독립 상태 + 최소 1개 보장 + 측정 중 닫기 확인.
```

**3단계 — 세션 설정 폼**
```
README "3. 세션 설정 화면" 을 구현해라. 기기 목록/지표 칩/앱 검색/세션 옵션/하단 시작 바.
빈 상태 3종 전부 포함 (기기 0대, 기기 미선택, 검색 결과 없음) —
screenshots/06, 07 참고. 지표 지원 판정은 doctor 응답을 쓴다.
```

**4단계 — 측정 중 + 마킹**
```
README "4. 측정 중 화면" 을 구현해라. screenshots/02-running-with-marks.png 과 맞춰라.
마킹은 입력+Enter, 빠른 칩 4개, 최신순 목록, 삭제. 정지 시 marks[] 로 저장.
README 에 적힌 "알려진 이슈"(마킹 3개 이상 + 낮은 뷰포트에서 정지 버튼 밀림)를 해결해라 —
정지 버튼을 마킹 블록 위로 올리거나 목록 max-height 를 낮추는 쪽으로.
```

**5단계 — 기록 드로어 + 공통 컴포넌트**
```
README "5. 기록 드로어", "6. 확인 다이얼로그", "7. 로딩 오버레이", "8. CLI 로그 스트립" 을 구현해라.
screenshots/03, 04, 05 참고. 로딩 오버레이와 확인 다이얼로그는 각각 하나의 재사용 컴포넌트여야 한다.
```

## 3) 대시보드를 나중에 시킬 때

```
기록을 클릭하면 열리는 세션 대시보드를 설계·구현하고 싶다.
runs/<디렉토리>/result.json 의 스키마를 먼저 읽고, 어떤 지표를 어떤 시각화로 보여줄지
2~3가지 안을 제안해라. 구현은 합의 후에.
GUI 의 기존 다크 토큰과 타이포를 그대로 쓰고, 측정 못 한 지표(unsupported / skipped)를
숨기지 말고 이유와 함께 드러내는 게 중요하다.
```

## 팁

- 이 폴더를 리포지토리 루트에 두고 시작하면 Claude Code 가 경로를 헤매지 않습니다.
- 프로토타입 HTML 을 직접 열어보고 싶다면 `python3 -m http.server` 로 이 폴더를 서빙하면 됩니다(디자인 시스템 CSS 경로가 상대경로라 file:// 로는 스타일이 깨질 수 있습니다).
- 스타일 값을 물어보면 README 의 해당 절 이름을 그대로 지목해 주세요 — 픽셀·hex 단위로 다 적혀 있습니다.
