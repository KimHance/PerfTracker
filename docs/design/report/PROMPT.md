# 클로드 디자인에게 넘길 프롬프트

아래 `---` 사이를 그대로 붙여넣고, 같은 디렉토리의 파일 7개를 함께 올린다.

```
CONTRACT.md            데이터 계약 · 깨면 안 되는 규칙   ← 반드시 먼저 읽힐 것
manifest.draft.ts      매니페스트 초안 (팩토리 구조)
samples/full.json      실기기 세션 — 7개 지표 다 나옴 (sdk 36, 릴리스 빌드)
samples/legacy.json    실기기 세션 — 새 필드가 통째로 없음 (구버전 캡처)
samples/low-end.json   실기기 세션 — 지표 2개 미지원 · 3개 부분수집 (sdk 30, 디버그 빌드)
samples/schema.json    JSON Schema (필드 뜻과 함정)
interaction-reference.html         상호작용 레퍼런스 (디자인 아님)
```

---

## 만들 것

안드로이드 앱 성능 측정 도구 **PerfTracker** 의 **세션 보고서 화면**.

로컬호스트 웹 GUI 에 측정 기록 목록이 있고, 항목을 누르면 그 세션의 보고서가 열린다.
지금 그 보고서 화면이 없다. 그것을 만든다.

React 19 + Vite. 외부 요청 0회(글꼴·아이콘 포함 전부 자체 호스팅). 차트 라이브러리는 쓰지 않는다 —
SVG 를 직접 그린다(현재 화면이 그렇고, 번들에 240KB 짜리 의존성을 새로 들이지 않는다).

## 가장 중요한 요구: 팩토리여야 한다

**지표마다 컴포넌트를 만들지 말 것.** 데이터 모양은 여섯 가지뿐이고
(`distribution` `series` `bars` `delta` `pairs` `stat`), 각 지표는 **자기 모양과 데이터 위치를
선언**한다. 렌더러는 모양만 안다.

```
지표가 늘어난다  →  매니페스트에 한 줄
새 모양이 생긴다 →  그때만 kind 를 하나 늘린다
```

실제로 이 도구는 지금도 필드가 계속 늘고 있다. 최근에 기기 CPU 초당 추이 · 기기 메모리 초당
추이 · 앱 빌드 속성 5개가 한 번에 들어왔다. 다음에 로그 원문 목록과 네트워크 초당 추이가
들어올 예정이다. **그때 화면 코드를 안 고치는 것**이 이 설계의 목적이다.

구조 초안은 `manifest.draft.ts` 에 있다. 타입 이름과 구조는 바꿔도 되고,
`CONTRACT.md` 의 규칙만 지키면 된다.

## 절대 규칙 넷 (자세한 것은 CONTRACT.md)

1. **`null` 은 `0` 이 아니다.** 값 없는 초에서 선을 잇지 않는다 — 이으면 재지 않은 구간에
   직선이 그어지고 그 직선은 데이터처럼 보인다. 끊고, 끊긴 자리를 남긴다.
2. **판정하지 않는다.** "느리다/좋다/위험" 을 내지 않는다. 임계선·점수·등급·좋고나쁨 색 없음.
   `references` 에 구글 기준치가 들어 있지만 **비교에 쓰지 않는다** — 기록만 하는 자리다.
   기준선을 고르는 일은 데이터를 읽는 사람의 몫이라는 것이 이 도구의 설계 전제다.
3. **못 잰 것을 숨기지 않는다.** `status` 가 `partial`/`skipped` 면 화면에 보여야 하고,
   필드가 없으면 블록을 사라지게 하지 말고 "수집 안 함" 으로 남긴다.
4. **시간축은 하나다.** 모든 `t_s` 와 `session.marks[].offset_ms/1000` 이 같은 0초를 쓴다.
   그래서 여러 그래프에서 같은 순간을 짚을 수 있다.

## 상호작용 (interaction-reference.html 에 동작하는 형태로 있음)

- **분포**: 막대에 올리면 그 막대만 진해지고 나머지는 흐려진다. 툴팁이 마우스를 따라가며
  구간·개수·비율·누적비율. 빈 구간이 길면 축을 끊고 **끊었다고 적는다.**
- **시계열**: 한 칸에 올리면 **모든 시계열 칸이 같은 초를 가리킨다.** 각 칸이 제목줄에
  자기 값을 띄우고 선 위의 그 점을 짚는다. "CPU 가 튄 그 순간 프레임은 어땠나" 를
  눈을 안 옮기고 읽게 하는 것이 목적이다.
- **표식(mark)**: 사람이 측정 중에 남긴 메모다. 모든 시계열에 같은 자리로 얹히고,
  범례를 짚으면 그 초로 전파된다.

이 동작들은 유지하되, **더 나은 방법이 있으면 바꿔도 된다.**

## 시각 디자인은 전부 맡긴다

`interaction-reference.html` 은 **상호작용 레퍼런스이지 디자인 시안이 아니다.** 시스템 폰트에
회색조로 일부러 밋밋하게 만들었다. 색·글꼴·여백·레이아웃·모션은 처음부터 정해 달라.

다만 이것은 **읽고 판단하는 화면**이지 대시보드 장식이 아니다. 이 도구를 쓰는 사람은
"이 세션에서 무슨 일이 있었나" 를 알고 싶어 하고, 그 답을 **자기가** 내린다.
숫자가 정확히 읽히는 것이 예쁜 것보다 우선이다. 숫자 정렬(tabular-nums)은 필수.

라이트/다크 둘 다. 한국어가 본문이고 숫자·식별자는 라틴이다.

## 참고

- **표본 셋 다 오류 없이 렌더되어야 한다. 전부 실기기 실측이다.**
  특히 `low-end.json` — 저사양 기기(Android 11)라 `frame` 과 `network` 는 **지표가 통째로
  없고**(`status: unsupported`), `cpu` 는 **기기 쪽은 나오는데 앱 쪽만 `null`** 이며,
  `log` 는 `no_log_entries`(재 봤더니 0건 — 모르는 것과 다르다), 화면 주사율은 `null`,
  그리고 **디버그 빌드**(`debuggable: true`)를 잰 세션이다.
  이 파일이 규칙 1·3 을 가장 많이 건드리므로 여기서 먼저 맞춰 보는 것이 빠르다.
- `samples/schema.json` 에 필드마다 뜻과 함정이 적혀 있다. 특히 `null` 과 `0` 의 차이.
- 세션이 아직 측정 중일 수도 있다(`session.state === 'running'`). 그때
  `ended_at`·`duration_ms`·`state_after` 는 `null` 이다.
