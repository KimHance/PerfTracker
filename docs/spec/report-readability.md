# 보고서 가독성 — 글자 · 대비 · 위계를 숫자로 맞추고 요약 배지를 바로잡기

| 항목 | 값 |
|---|---|
| 기능 | report-readability |
| 마지막 변경 | 2026-10-11 · RR-1 ~ RR-9 처음 — 최소 12px · 대비 AA · 세 층 위계 · 요약 타일 · 경로 라벨 두 줄 · 배지가 잰 0 을 세지 않음 |
| 디자인 | docs/design/report-readability.md |
| 항목 ID | RR-<번호> (예 RR-2) |

대상은 **세션 보고서**(`perftracker report` 파일 하나 · `perftracker open` 의 같은 보고서 화면)뿐이다 — 측정 화면은 아니다.
이 문서는 보고서 전체를 다시 적지 않는다 (백필 안 함). 보고서의 지금 모양은 `docs/design/report/HANDOFF.md`,
이번에 바꾸는 것만 여기. 근거 측정은 2026-10-11 실기기 SM-S901N · YouTube 진단 세션 보고서를 playwright(Chromium)로 1440 · 390 에서
잰 것이다 — 글자마다 `getComputedStyle` 크기 · 색 · 겹친 바탕으로 WCAG 2.x 대비, 글자 수 가중. 이 방법을 아래에서 「글자 측정」 이라 부른다.

## 기획

### 왜

- "보고서가 잘 안 보인다." 글자 측정에서 요약 탭 글자의 84.7% · 진단 탭의 99.7% 가 12px 미만이다 (원본 디자인 29.1%).
  표 본문 11.5px · 카드 제목 12.5px · 섹션 제목 10.5px — 섹션 제목이 본문보다 작고 카드 제목과 본문이 1px 차이라 층이 안 보인다.
- 요약 탭 글자의 13.5% 가 대비 4.5:1(AA) 미만이다 — 단위(3.82) · 머리 메타 라벨(4.27) · 푸터.
- 원본 디자인에 있던 **들어가는 자리**(맨 위 요약 타일)가 구현에서 빠졌다. 첫 화면에 큰 숫자가 하나뿐이고 카드 18장이 같은 무게다.
- 진단 탭 카드 라벨이 필드 경로 그대로(`target_process_slice_names_unfolded` …)라 읽히지 않고, 긴 기계 이름이 단어 중간에서 끊긴다
  (`…Shell$HomeA / ctivity`).
- **결함**: 레일 `요약 3` 배지는 "미수집 블록 수" 인데, 실제로 센 것은 `크래시 없음` · `ANR 없음` · `경고 없음` — 재 봤더니 0건(`[]`)이다.
  규칙 3 위반이고, 사용자가 보는 숫자가 틀렸다 (plan B6).

### 누구

| 누가 | 언제 쓰나 |
|---|---|
| 보고서를 읽는 사람 | 세션 하나를 훑고 어디부터 볼지 정할 때 · 노트북 1440 · 폰 390 |
| 보고서를 공유받는 사람 | 파일 하나를 열어 수치를 찾을 때 (⌘F 로 필드 경로를 찾기도) |

### 흐름

1. 보고서를 연다 → 요약 탭 맨 위에 지표마다 타일 하나 (값 · 단위 · 못 잰 이유 코드)
2. 섹션 제목 → 카드 제목 → 값 순으로 훑는다 — 크기가 층을 말한다
3. 카드 라벨은 우리말 단어로 읽고, 필드 경로는 바로 아래 줄에서 (⌘F 로 찾힌다)
4. 레일 배지 수 = 그 탭의 미수집 블록 수 — 따라가면 `수집 안 함` · `값 없음` 블록이 그 수만큼 있다
5. 진단 탭 slice 표 → 긴 이름이 `/` · `:` 같은 구분자에서 줄바꿈된다
